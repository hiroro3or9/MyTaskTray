# 表示するアプリで絞り込む

項目の「表示するアプリ」を開いて条件を書くと、**そのとき前面にあるウィンドウ**に応じて
メニューの中身が変わります。ターミナルならコマンド、チケット画面なら報告テンプレート、といった使い分けができます。

スマートアクション（クリップボードの中身）とは別の条件で、**両方を満たしたときだけ**表示されます。
「常に表示」の通常の項目にも掛かります。

| 欄 | 書き方 |
| --- | --- |
| アプリ | 実行ファイル名。カンマ区切りで複数書けます。`.exe` は省略でき、大文字小文字は区別しません |
| ウィンドウタイトル | 正規表現。空欄ならタイトルを見ません |

```text
アプリ:            chrome.exe, msedge.exe
ウィンドウタイトル:  /issues/
コピー文字列:       feature/issue-{clip:digits}

→ ブラウザでチケット画面を開いているときだけメニューに出る
```

実行ファイル名は入力欄の右の「▾」から選べます。ここには**トレイメニューを開いたときに前面だったアプリ**が
新しい順に数件出ます（メモリ上にだけ置き、設定ファイルにも履歴にも残しません）。
条件を付けた項目には、設定画面の一覧に「アプリ」のバッジが出ます。検索でも実行ファイル名やタイトルの式が対象になります。

### 判別できない場合は表示します

前面のウィンドウが無い、プロセス名を読めない、正規表現が 200 ミリ秒で終わらない――
こうした「判定できない」場合は、**条件に一致したものとして表示します**。
スマートアクションは出なくても気付きませんが、通常の項目が消えると
「あるはずの項目が無い」となり、原因も分かりません。迷ったら出す側に倒しています。

条件に合う項目が 1 つも無い場合は、メニューに `(chrome.exe で表示する項目がありません)` と出ます。

> ウィンドウタイトルは、アプリの言語・バージョン・開いているファイルで変わります。
> 実行ファイル名と違って安定した識別子ではないことに注意してください。

> 電卓や設定などのストアアプリは、前面ウィンドウが `ApplicationFrameHost.exe` として見えることがあり、
> 中の実際のアプリ名は取れません。
